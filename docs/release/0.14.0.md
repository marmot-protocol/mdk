# MDK 0.14.0

MDK 0.14.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.13.0 → 0.14.0 client upgrade guide](../integration/0.14.0.md) for required
constructor, record, error, header, storage and backup changes.

## Highlights

- Encrypted media files. Attachment bodies, download checkpoints, avatars and
  group images move out of the account database into encrypted per-file storage
  under the account's `media/` directory. Bodies already in the database move in
  the background, and a one-time compaction returns the freed space when the
  account is small enough.
- Manage storage. Hosts can show per-account and per-chat attachment usage,
  list the largest retained attachments, and remove a chat's attachments or
  everything older than a date. "Keep media" removes attachments past a chosen
  window (one year, six months or thirty days) on this device.
- Attachment handoff leases give the OS share sheet or another app a plaintext
  copy of one attachment, released explicitly.
- Account-wide attachment history pages list media across every chat with
  filters, bounded pages and change tokens.
- Public event previews resolve and cache `nostr:` references in messages, and
  report when the author deleted the event.
- Faster database opens. App databases now present their derived key to
  SQLCipher as a raw key instead of a passphrase, skipping a 256,000-iteration
  KDF on every open. Each existing database is rekeyed once on first open.
- Group changes can pause with a prompt: `GroupCatchingUp` while the device is
  still catching up, and `GroupCommitUndelivered` when the previous commit has
  not reached its relays for two minutes. The host acknowledges and retries;
  messages and leaving are never held.
- Invitations explain failures: a recipient whose only KeyPackages are
  obsolete, a lookup that ran out of time, or a member with no inbox route.
- Follow and unfollow edit the current follow list in place, keeping petnames,
  relay hints and other tags, and refuse instead of truncating a list of 2,048
  or more.
- WN Agent can edit an agent's own message (`edit_message`), and OpenClaw
  exposes it. Edits of messages that cannot be edited are refused before
  anything is published.
- MarmotKit runs MDK on its own two-to-four-thread runtime, so async calls
  awaited from the main thread no longer run MDK work there.
- Deployment services that used to be compiled in for White Noise (recovery
  relays, discovery indexers, media and image servers, Open Ranking, KeyPackage
  client preference, moderation namespace, keychain service) are now one
  host-supplied deployment record with a White Noise preset.
- Catch-up and delivery: ordered, complete offline catch-up; live group
  subscriptions batched 50 per REQ so accounts in many groups stay under relay
  REQ limits; epoch-gap recovery pages backwards through clamped relays;
  terminal relay rejections are no longer retried; stalled recovery routes stay
  retryable; self-update commits retry every missed relay.
- Onboarding relay diagnostics say which check produced each finding, why it
  ran, what it found and which actions apply to it.
- An unreachable relay no longer fails an account's activation or group sync,
  taking the inbox and every healthy group offline; its subscription is sent
  when the relay reconnects, and a group sync re-sends only the relay sets it
  changes. Sends and group changes no longer fail when the pre-send
  subscription refresh cannot reach a group's relays; convergence retries and
  signed-out accounts still require it. Opt-in relay telemetry
  exports activation and group-sync outcome counters.
- Fixes: the retention sweep no longer deletes messages still counted unread;
  a quarantined group no longer stalls every conversation's receives; iOS
  suspension no longer risks `0xdead10cc` termination; a Welcome built from a
  just-replaced KeyPackage can still be joined.
- QUIC agent-stream brokers are verified against bundled Mozilla roots, fixing
  an Android abort on the first handshake.
- Security updates: `quinn-proto`, `rustls`, `rustls-webpki`, `webpki-roots`,
  `negentropy` and `ctutils`.

## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact
cohort together.

- Every MarmotKit constructor takes a `MarmotDeploymentFfi`, and
  `MarmotOptions.deployment` is required. White Noise apps pass
  `marmotDeploymentWhiteNoise()`. Other hosts that used the platform keychain
  without a `SecretStore` must keep `keychainService = "com.marmot.whitenoise"`,
  or their existing account secrets are no longer found.
- `MarmotKitError` gains `InvalidEditTarget`, `InvalidPublicEventReferences`,
  `DirectoryLookupIncomplete`, `FollowListTooLarge`, `GroupCatchingUp`,
  `GroupCommitUndelivered` and `StorageFull`; `MissingKeyPackage` gains a
  `reason`. Some failures that used to arrive as `Runtime` or
  `InvalidKeyPackageEvent` now use the new variants.
- `AttachmentTransferStateFfi` gains `StorageBlocked` and `CleanedBySetting`;
  `RetentionSweepStatusFfi` loses `DeferredScanExhausted`.
- `OnboardingFindingFfi` gains `context`, `purpose`, `outcome`,
  `declaredCapability`, `actions` and `observedRevision` with no binding
  defaults, and `OnboardingIssueFfi` gains `InspectionCompleted`.

C hosts must recompile and update every `marmot_client_new*` call: each takes a
required `const struct MarmotDeployment *`. `MarmotRetentionSweepStatus` drops
`DEFERRED_SCAN_EXHAUSTED`, so `FAILED` moves from 5 to 4. `MarmotOnboardingFinding`
changes layout, `MarmotOnboardingIssue` appends `InspectionCompleted` (21), and
statuses 101–107 are new. No other existing struct layout changed.

Rust hosts: `MarmotAppConfig::default()` is now the neutral deployment; use
`MarmotAppConfig::white_noise()` to keep White Noise's services. `MarmotApp`'s
directory methods moved to `app.directory()` and return `DirectoryError`.
`AppError` gains six variants, ingestion borrows its input, and
`NostrAdapterMetrics` and `RelayTelemetryRollup` gain counter fields.

Account databases migrate from schema 107 through 116 on first open, the
directory cache from 1 to 2, and every app database is rekeyed to a raw
SQLCipher key. None of this rewrites message history, but the rekey rewrites
every database page once. Downgrade is unsupported: 0.13.0 cannot open the
rekeyed databases. Keep a device-local copy of the account directory before
upgrading, and exclude the account directory, including `media/` and
`handoff/`, from iCloud and Android backups. See the
[storage-format contract](../marmot-architecture/storage-format-v2.md).

WN Agent and its plugins must be upgraded together: a 0.14.0 plugin calling
`edit_message` on a 0.13.0 connector sees the socket close without an error.

## Known issues

- [#2237](https://github.com/marmot-protocol/mdk/issues/2237): a message that
  arrives more than five epochs too late stays undecryptable without a "history
  may be incomplete" notice.
- Group-change prompts: undecryptable traffic can hold a group's changes behind
  `GroupCatchingUp` ([#2277](https://github.com/marmot-protocol/mdk/issues/2277)),
  no bounded catch-up runs before the refusal
  ([#2283](https://github.com/marmot-protocol/mdk/issues/2283)), and an
  acknowledgement cannot be withdrawn
  ([#2389](https://github.com/marmot-protocol/mdk/issues/2389)). Healthy relays
  can look owed for a short time after a commit
  ([#2286](https://github.com/marmot-protocol/mdk/issues/2286)); the two-minute
  grace keeps that from prompting.
- [#2253](https://github.com/marmot-protocol/mdk/issues/2253): group data
  updates move the app-data extension to the end of the group context, which
  implementations that preserve extension order reject.
- [#2158](https://github.com/marmot-protocol/mdk/issues/2158): an upload still
  in flight when the group epoch advances is lost.
- The one-time rekey has not been measured on large databases or on devices
  beyond a Pixel 8 Pro fixture; see the upgrade guide.
- WN Agent's control socket still grants its whole API to any authenticated
  client ([#1445](https://github.com/marmot-protocol/mdk/issues/1445)), and
  reports the new group-change refusals as a generic `app_error`.

## Release artifacts

- `v0.14.0`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.14.0`: WN Agent, terminal harness binaries, gateway plugins and
  checksum-paired installers. This track keeps its existing prerelease status.
- `marmotkit-v0.14.0`: iOS/macOS XCFrameworks, shared Swift source, platform
  privacy resources, Android Kotlin and all four JNI ABIs with
  `android-elf.json`, manifests and checksums.
- `marmotc-v0.14.0`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md). Dated
`0.14.0-nightly.*` builds are for testing only; pin this release instead.
