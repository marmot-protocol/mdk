# MDK 0.10.1

MDK 0.10.1 updates the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit.

## Highlights

- Durable avatar storage, acquisition and native asset access keep chat-list
  and conversation identities available through the app runtime and bindings.
- Accepted message edits share effective text across timelines, replies and
  chat previews, with a separate paged edit history.
- Authenticated group-system previews expose prepared actor and subject
  identities. Reactions on system rows no longer displace valid chat previews.
- Stored conversations open before live recovery completes, and conversation
  windows remain responsive while sends are in progress.
- Encrypted group reports, shared dismissal labels and admin message removal
  are available in Rust, Swift/Kotlin and C. Upgrade all participants for
  consistent moderation; older peers may retain admin-removed content.
- Invite acceptance and media downloads have bounded waits and retry budgets.
  Founding Welcome publication overlaps subscription setup.
- OpenClaw retries failed managed welcomer reconciliation and prevents an old
  inbound setup attempt from stopping its replacement generation.

## Compatibility and adoption

Update generated Swift/Kotlin source and native libraries together from the
same immutable release. C consumers must update the header and library
together because output record layouts have changed.

Apple bundles now contain raw static-library XCFrameworks and a separately
checksummed privacy asset. Keep the remote binary target; stage the matching
Swift source and platform privacy file in its Swift wrapper, rename the latter
to `PrivacyInfo.xcprivacy`, and declare `resources: [.copy("PrivacyInfo.xcprivacy")]`.
Every consuming app and extension must depend on that wrapper. Remove obsolete
FFI framework embedding steps. A binary-only update loses SDK privacy delivery.
See the [distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md) and
[consumer adoption tracking](https://github.com/marmot-protocol/mdk/issues/1874).
The privacy audit's native required-reason and SDK-signing questions remain
open for host App Store submission; resource validation does not resolve them.

Account databases advance through migrations 76–80: accepted edits, avatar
storage and acquisition, content reports, and avatar target lookup. Back up or
export before upgrading. Downgrade after migration is unsupported; re-upgrade
or restore a pre-upgrade account database/export. Never remove migration rows.
See the [storage-format definition and compatibility evidence](../marmot-architecture/storage-format-v2.md).
Upgrades from before migration 47 also require at least 3.25 times the account
database size in free space for its table rebuild and gradual promotion.

- `v0.10.1`: MDK source snapshot.
- `wn-agent-v0.10.1`: WN Agent and terminal harness binaries, gateway plugins,

- `marmotkit-v0.10.1`: iOS/macOS XCFrameworks, shared Swift source, separate
  platform privacy assets, Android Kotlin and all four JNI ABIs, manifests and
  checksums.
- `marmotc-v0.10.1`: C ABI bundle and checksum.

Verify sibling SHA-256 files and manifest source/version metadata. Apple
binary ZIPs also provide SwiftPM checksums. Use matched release inputs.
