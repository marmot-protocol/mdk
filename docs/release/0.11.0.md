# MDK 0.11.0

MDK 0.11.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.10.4 → 0.11.0 client upgrade guide](../integration/0.11.0.md) for required
record, schema, configuration and host UI changes.

## Highlights

- Account recovery v2 completes lost or incremental history only when every
  required relay finishes an untruncated NIP-77 comparison that covers the gap.
  Recovery runs off the account worker and reuses live subscriptions instead of
  replaying history, and one comparison job replaces the inline executor.
- When recovery cannot prove history complete, it stops retrying and raises a
  durable "history may be incomplete" notice. Hosts should show these notices
  and let the user dismiss them.
- A full account delivery queue now spills to the account database instead of
  dropping deliveries. A relay notification lag no longer closes the account
  route, and end-of-stored-events notifications lost in a lag are repaired.
- The transport cursor advances on live delivery, so a restart no longer
  re-downloads what the account already received live. History REQs for post-join
  maintenance and retained routes now start from a floor instead of fetching
  full history.
- New optional APIs: durable edits of pending token-aware sends, encrypted
  NIP-88 polls, stateless Nostr event verification, more host performance
  stages and a v5 audit OTLP destination. With v5 audit enabled, account recovery
  decisions, transport-cursor moves and lost-EOSE repairs are recorded as new
  v5-only event kinds.
- OpenClaw enforces an inbound sender policy that denies every sender until one
  is configured. Hermes adds opt-in presence reactions, and Codex accepts
  non-image attachments.
- Android 64-bit JNI libraries use 16 KB ELF load-segment alignment. Apple
  archives no longer ship LLVM bitcode.


## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort
together. `MarmotEventFfi` / `MarmotEvent`, `GroupRecoveryStatusFfi` /
`MarmotGroupRecoveryStatus`, timeline records (poll projection) and
`HostPerformanceOperationFfi` changed. Rebuild consumers and update exhaustive
matches and manually constructed records. No existing method signature changed.

Rust hosts: `MarmotAppConfig` removes `dev_epoch_backfill_eose_wait_ms` and
`dev_epoch_backfill_execution_quantum_ms`, adds `recovery_operated_relays` (it
defaults to the two `whitenoise.chat` relays), and `AppPriorNostrRoute` gains
`replaced_at`. `nostr` / `nostr-sdk` now come from a pinned fork revision.

Account databases migrate from schema 89 through 98 on first open. Back up before
upgrading; downgrade is unsupported. Re-upgrade or restore a pre-upgrade
database/export instead of removing migration rows. See the
[storage-format contract](../marmot-architecture/storage-format-v2.md). After upgrade,
an account that overflowed on 0.10.4 can show a "history may be incomplete" notice,
and a group already stuck on 0.10.4 keeps its automatic-recovery-failed status for
up to an hour. The upgrade guide describes both.

## Known issues

- [#2086](https://github.com/marmot-protocol/mdk/issues/2086): during a large
  catch-up, a member can advance more than five epochs past application messages
  it has not yet downloaded. Those messages cannot then be decrypted, and no notice
  is raised. The failure is intermittent and was already present before this
  release.
- The Apple required-reason and SDK-signing questions remain tracked in
  [#1874](https://github.com/marmot-protocol/mdk/issues/1874).

## Release artifacts

- `v0.11.0`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.11.0`: WN Agent, terminal harness binaries, gateway plugins and
  checksum-paired installers. This track keeps its existing prerelease status.
  Install only from the versioned release; the mutable `wn-agent-latest` alias is
  retired.
- `marmotkit-v0.11.0`: iOS/macOS XCFrameworks, shared Swift source, platform privacy
  resources, Android Kotlin and all four JNI ABIs with `android-elf.json`, manifests
  and checksums.
- `marmotc-v0.11.0`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md).
