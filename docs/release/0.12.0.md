# MDK 0.12.0

MDK 0.12.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.11.0 → 0.12.0 client upgrade guide](../integration/0.12.0.md) for required
record, error, header and storage changes.

## Highlights

- NIP-30 custom emoji. `sendTaggedText`, `sendTaggedMedia` and `reactWithMedia`
  send chats and reactions carrying `["emoji", shortcode, url]` tags whose images
  are encrypted Marmot media. Conversation-window chat rows keep those tags, and
  reactions name the kind-7 whose image `listMedia` returns. Peers on 0.12.0 can
  send them, so render them.
- Per-voter poll results. `pollVotes` pages who chose each option, using the same
  rules as the poll tally.
- Application-owned group components. `groupAppComponent` and
  `updateAppComponent` read and admin-update opaque settings (ids `0xf000` and
  up) carried in MLS group state, so they survive message expiry and reach new
  members in their Welcome.
- Hosts can declare a kind-10050 inbox relay list separately from
  `default_relays` on identity creation, login, relay-list publication and
  onboarding.
- Attachments: agent-sent files no longer stay downloading forever, missing-key
  deferrals end after about eight minutes, an explicit tap
  (`requestExplicitAttachment`) promotes demand without resetting retry budgets,
  and successfully sent files are retained locally for the sender.
- A muted chat still notifies on a direct mention of the account.
- Recovery: a route change no longer resets recovery for every route, recovery
  parks behind a required relay that never answers, catch-up no longer holds
  the account worker for recovery, and group creation no longer rebuilds the
  routing table.
- Publishing: retained per-account publishers cut a measured complete
  send-with-push call from about 1.9 s to 0.14 s mean against the operated relays.
- WN Agent: admin agents can rename groups and edit descriptions
  (`group_profile_update`, Hermes `marmot_group_profile`); `account_publish_profile`
  merges into the published profile instead of replacing it; files work in both
  directions for Codex, OpenCode and Pi.

## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort
together. `MarmotKitError` gains `InvalidAppComponent`, and
`ConversationReactionFfi` gains `reactionMessageIdHex` with no binding default.
Update exhaustive error handling and host-constructed reaction records. Six
account methods gained a trailing `inboxRelays` parameter that defaults to empty
in Swift and Kotlin.

C hosts must recompile: the six account entry points gain trailing
`inbox_relays` / `inbox_relays_len` arguments, `MarmotMediaUploadRequest` and
`MarmotConversationReaction` gain trailing fields, and
`MARMOT_STATUS_INVALID_APP_COMPONENT` (95) is new.

Rust hosts: `AccountSetupRequest`, `AccountRelayListBootstrap`,
`OnboardingOptions`, `MediaUploadRequest` and `ConversationReaction` gain fields,
`AppError` gains `InvalidAppComponent`, and the engine's
`GroupEvent::MessageReceived` gains `encrypted_media_secret`. An expired account
worker ready-wait now reports `account worker startup timed out at <stage>`.

Account databases migrate from schema 98 through 101 on first open. Back up
before upgrading; downgrade is unsupported. See the
[storage-format contract](../marmot-architecture/storage-format-v2.md).

## Known issues

- [#2086](https://github.com/marmot-protocol/mdk/issues/2086): during a large
  catch-up, a member can advance more than five epochs past application messages
  it has not yet downloaded and lose them silently. This release fixes the
  related attachment-key case but not the message case.
- The Apple required-reason and SDK-signing questions remain tracked in
  [#1874](https://github.com/marmot-protocol/mdk/issues/1874).
- WN Agent's control socket still grants its whole API to any authenticated
  client; capability-scoped grants remain tracked in
  [#1445](https://github.com/marmot-protocol/mdk/issues/1445).

## Release artifacts

- `v0.12.0`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.12.0`: WN Agent, terminal harness binaries, gateway plugins and
  checksum-paired installers. This track keeps its existing prerelease status.
- `marmotkit-v0.12.0`: iOS/macOS XCFrameworks, shared Swift source, platform privacy
  resources, Android Kotlin and all four JNI ABIs with `android-elf.json`, manifests
  and checksums.
- `marmotc-v0.12.0`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md).
