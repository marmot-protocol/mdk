# MDK 0.19.0

Thread messages now behave like chat across clients. WN Agent and its plugins deliver replies as durable messages,
and MDK retires the QUIC live text preview. Apps upgrading from 0.18.0 should update their bindings, draft composer
and every process that opens an account database. See the [0.18.0 → 0.19.0 integration guide](../integration/0.19.0.md).

- **Replies and threads.** A thread view can send a NIP-22 message with `sendThreadMessage`. Timelines and reply
  previews expose its root and parent. A client can show a one-level quote and continue using `replyToMessage`.
  Thread messages update chat order, unread counts, mentions and notifications. WN Agent delivers them live and
  on replay, and suppresses the original content of messages deleted before it writes them to the agent.
- **Agent compatibility.** Remove live preview publishers, watchers and `wn stream` commands. Custom agent-control v2
  clients must use `send_final`. New groups omit the retired component. Existing groups can still validate it and
  read durable replies.
- **Storage and bindings.** Account databases advance from schema 216 to 218, repairing older thread messages and
  removing stream-start timeline rows. A 0.18.0 process cannot reopen a migrated account. Roll out matching bindings
  and binaries to the app and extensions together. C clients must rebuild for changed record layouts and enum values.
- **Draft attachments.** A revisioned input save keeps attachments it omits, including files a composer has yet to
  load. Send an explicit removal when the user deletes an attachment.
- **Rust hosts.** Tagged text, replies, edits and custom events can use a client token for crash-safe submission.
  After restart, replaying the same request with its token returns the original message ID.
- **Linked devices.** Invitation answers are resent promptly when a device-group update or its commit loses a fork.
  A sign-out waiting on device removal also stops waking maintenance every 15 seconds.
