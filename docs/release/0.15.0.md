# MDK 0.15.0

MDK 0.15.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.14.0 → 0.15.0 client upgrade guide](../integration/0.15.0.md) for required
record, error, event, header, storage and interoperability changes.

## Highlights

- Accounts with several devices. Creating a group or inviting adds every
  device of each account (up to 20 KeyPackages published in the last 30 days),
  and members are listed once per account with a `device_count`. A device joins
  only through the Welcome that names its own KeyPackage. New groups whose
  founding devices all support it require the account-devices component
  (`marmot.group.account-devices.v1`); an admin can turn it on in an existing
  group with `enable_account_devices`.
- Automatic rejoin. An account worker rejoins a group copy that became
  `Unrecoverable` through an authenticated handshake with an admin device over
  the account inbox, with bounded retries.
- Recovery owns account history. Catch-up after time offline is bounded and
  paced, history arrives in order, newer live messages wait until the fetched
  backlog is admitted, and `account_recovery_status` reports groups still
  catching up. A rejoined group raises one `BeforeRejoin` history notice.
- Chat-list queries. Typed filters (unread, pinned, archived, direct, group,
  muted, chat text, message text and more) combine with `AND`/`OR`/`NOT`, and
  hosts can select every chat a filter matches for bulk actions.
- Timeline search filters by sender, date range and attachment type, and
  matches non-ASCII text case-insensitively.
- Sonar-compatible sticker packs, NIP-51 custom emoji sets with pinned local
  installs, and custom reaction artwork lookup.
- Leaving as an admin. A blocked leave (the last active admin) is shown and can
  be cancelled with `cancel_leave`. Sign-out steps an admin down and leaves its
  chats before wiping.
- Push notifications reach every device of a member, newly added members learn
  existing tokens, and devices repair missed tokens inside each group.
- Sends: queued offline sends publish after reconnect, a send never overtakes
  one queued before it, a Welcome waits until its Commit is published, failed
  convergence retries back off and park, and refused queued intents are retired
  with `QueuedIntentRefused`. Oversized events report `EventTooLarge`.
- KeyPackages are valid for 30 days and refreshed weekly. Sign-out deletes only
  this device's KeyPackage slot instead of every device's.
- External signers are no longer asked to sign the identity proof again on every
  reopen.
- Pasted `note1`, hex and author-only `nevent` references now resolve through
  the deployment's discovery indexers and the author's write relays.
- WN Agent: `wn-agent doctor`, a connector-only `install-wn-agent.sh` for your
  own control-socket client, historical attachment download with leases,
  founding co-admins, and default relays with published relay-list adoption.
- Lower idle cost: maintenance ticks with nothing to do no longer open write
  transactions, `wnd` no longer grows about 3 MB per request, and cached user
  search ranks in SQL and finds people past the 10,000th cached identity.
- Security: the pinned Nostr SDK rejects tampered events even when their id is
  cached, directory events are verified before they are forwarded or stored,
  account records are written owner-only, local audit files expire after 30
  days, and `elliptic-curve`/HPKE (RUSTSEC-2026-0387), `openssl` and the
  OpenClaw plugin's npm dependencies are updated.

Experimental device groups (pairing, linked devices, sign-in review, history
transfer and backups) continue behind the `dev-device-groups` build feature and
`new_with_experimental_device_groups`. Ordinary builds and constructors keep them
off and refuse accounts that already use them.

## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact
cohort together.

- Interoperability: every 0.15 device advertises the account-devices
  component. A new group requires it when the creator and every device added
  at creation advertise it, and 0.14 or older clients cannot then be invited
  into it. Existing groups are unchanged until an admin enables it.
- `TimelineMessageQueryFfi` adds `sender`, `since`, `until` and
  `cursorGroupId` with no binding defaults. `MarmotDeploymentFfi` drops
  `keyPackagePreferredClients` and `keyPackageLastClients`.
- `MarmotKitError` gains 22 cases, including `EventTooLarge`,
  `MediaReferenceStaleEpoch`, `MediaReferenceEpochUnsettled`, `LeaveNotBlocked`,
  `InvalidChatListQuery`, `AccountUnlinked`, the sticker and emoji-set errors,
  and `GroupRecoveryUnsettled`/`GroupRecoverySourceMismatch`. Some failures that
  used to arrive as `Runtime`, `Publish` or `InvalidMediaReference` now use them,
  and busy, closed or full storage arrives as `StorageBusy`, `StorageClosed` or
  `StorageFull`.
- `MarmotEventFfi` gains eight cases, and `WelcomeDeliveryPending` gains
  `sizeClass`. `HistoryNoticeCauseFfi` gains `UnprovenHistory` and
  `BeforeRejoin`; `SelfMembershipFfi` and `ConversationParticipationFfi` gain
  `DeviceRemoved`; `GroupEventKindFfi` gains `QueuedIntentRefused`.
- Media references saved by 0.14 lack `sourceEpochIdentity`; sending one is
  refused with `MediaReferenceStaleEpoch`, so re-upload instead.
- Admin invitees must step down before declining an invitation, and
  `OnboardingIssueFfi::MultiDeviceUnsupported` is no longer produced.

C hosts must recompile. `marmot_deployment_set_key_package_client_preference`
is removed. `MarmotMediaAttachmentReference` gains `source_epoch_identity`
mid-struct; message, timeline, chat-list preview and notification records gain
a `sticker` pointer mid-struct; `MarmotTimelineMessageRecord` gains
`recipient_confirmed` mid-struct; `MarmotClientOptions` and
`MarmotTimelineMessageQuery` gain trailing fields. Statuses 108–129 and enum
values are appended; none is renumbered.

Rust hosts: `cgka-session` is now `marmot-session`, `TimelineMessageQuery` and
chat-list query types gain fields and variants, `AppError` gains variants, and
the diagnostics exporters move to `marmot-observability`. See the upgrade guide.

Account databases migrate from schema 116 through 201 on first open.
Downgrade is unsupported: 0.14.0 refuses the migrated database. Keep a
device-local copy of the account directory before upgrading. See the
[storage-format contract](../marmot-architecture/storage-format-v2.md).

Building from source now needs the Odin compiler (`scripts/install-odin.sh`, or
set `ODIN`), because Markdown parsing moved to Odin. Published artifacts are
unaffected.

WN Agent and its plugins must be upgraded together: a 0.15.0 client sending a
new request, such as `group_create_capabilities`, to a 0.14.0 connector sees
the socket close without an error. The OpenClaw plugin requires OpenClaw
2026.10.10 or newer and Node 24.22.1+ (24.x) or 26.12.1+.

## Known issues

- Still open from 0.14.0:
  [#2237](https://github.com/marmot-protocol/mdk/issues/2237) (late messages
  more than five epochs behind),
  [#2277](https://github.com/marmot-protocol/mdk/issues/2277),
  [#2283](https://github.com/marmot-protocol/mdk/issues/2283),
  [#2389](https://github.com/marmot-protocol/mdk/issues/2389) and
  [#2286](https://github.com/marmot-protocol/mdk/issues/2286) (group-change
  prompts), [#2253](https://github.com/marmot-protocol/mdk/issues/2253) (group
  data extension order), [#2158](https://github.com/marmot-protocol/mdk/issues/2158)
  (an upload in flight across an epoch change is lost) and
  [#1445](https://github.com/marmot-protocol/mdk/issues/1445) (WN Agent's
  control socket grants its whole API to any authenticated client).
- Adding every device of an account is best effort: a device whose KeyPackage a
  relay does not return in time is left out until the account is invited
  again, and an account with 500 or more KeyPackage slots cannot be invited.
- Right after a reconnect, a new send can still go out ahead of older unsent
  ones.
- A failed legacy group create in an earlier release can have left orphaned
  MLS state; 0.15 stops creating it but does not purge it.
- Migration 0175 refuses to open an account whose saved outbound fanout or
  group evolution does not decode, rather than risk reusing a send reference.
- The automatic-rejoin handshake's inner event kind is still under discussion
  ([marmot#451](https://github.com/marmot-protocol/marmot/issues/451)).

## Release artifacts

- `v0.15.0`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.15.0`: WN Agent, terminal harness binaries, gateway plugins and
  checksum-paired installers, now including `install-wn-agent.sh`.
- `marmotkit-v0.15.0`: iOS/macOS XCFrameworks, shared Swift source, platform
  privacy resources, Android Kotlin and all four JNI ABIs with
  `android-elf.json`, manifests and checksums.
- `marmotc-v0.15.0`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md). Dated
`0.15.0-nightly.*` builds are for testing only; pin this release instead.
