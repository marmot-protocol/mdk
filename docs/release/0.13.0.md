# MDK 0.13.0

MDK 0.13.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.12.0 → 0.13.0 client upgrade guide](../integration/0.13.0.md) for required
record, error, event, header and storage changes.

## Highlights

- Large attachments. `uploadMediaFiles` uploads from a file path with progress
  and cancellation instead of passing whole files as byte arrays, and large
  downloads stream into private files with resumable checkpoints.
- Private moderation reports. `submitModerationReport` sends a NIP-56 report,
  gift-wrapped per NIP-59, to the deployment's moderation team. Relays cannot see
  who reported whom, and reports carry no message, group or relay identifiers.
- Onboarding: `createIdentityWithInitialProfile` publishes the chosen name as a
  new account's first profile, so contacts never see the generated default.
  `proposeOnboardingRelayRepair` previews a lossless relay-list repair before
  approval, and manual relay edits keep untouched tags as they were.
- Message details: `messageReactions` returns every reaction on one message.
  Markdown gains local-time timestamp nodes. Attachment history marks inline
  custom-emoji artwork so galleries can leave it out.
- Polls can be created in direct conversations.
- Chat list: presented rows carry an opaque draft version, so a host can tell a
  newer draft from the one it captured for sending.
- Opt-in SOCKS5 routing (`WN_SOCKS5_*`) covers relays, media, directory reads,
  collectors and C NIP-46 sessions, and never falls back to a direct connection.
- Opt-in native startup diagnostics report anonymous startup and migration
  phases for slow-open investigations.
- Catch-up: missed group history arrives in batched requests of up to 256
  events and, when the backlog is larger than one pass, oldest first. Commits
  no longer routinely move a member more than five epochs past messages it has
  not downloaded yet ([#2086](https://github.com/marmot-protocol/mdk/issues/2086)).
- Relays that refuse a live subscription with `CLOSED` no longer leave it counted
  as live. Refusals are audited and counted in relay stats, and sync drains stop
  waiting for them.
- Sends: a message queued while the group converged is no longer shown as
  failed after everyone else received it, and durable sends keep progressing
  through recovery and relay retries.
- Invitations recover a member's KeyPackage from discovery relays when their
  advertised outboxes do not have one.
- Marmot C adds per-account NIP-46 signer sessions (beta).
- WN Agent adds the `wn-goose` harness for Goose and carries account relay-list
  reads and edits on the control surface.

## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort
together. No existing exported method changed its signature, but:

- `MarmotKitError` gains five moderation-report variants.
- Native events gain `LocalGroupCopyTerminated`, `LocalGroupCopyRestored` and
  `GroupMemberLeavesRemoved`; `MarkdownInlineFfi` gains `Timestamp`.
- `AttachmentEntryFfi.role`, `PresentedChatRowFfi.draftVersion` and
  `OnboardingRepairProposalFfi.relayRepair` are new fields without binding
  defaults. Update exhaustive handling and host-constructed records.

C hosts must recompile: `MarmotAttachmentEntry`, `MarmotPresentedChatRow` and
`MarmotOnboardingRepairProposal` change layout, new event and Markdown inline
tags are appended, statuses 96–100 are new, and relay-repair preview strings are
JSON-encoded.

Rust hosts: `AppError`, `GroupEvent`, `MarmotAppConfig`, `AttachmentEntry`,
`RelaySyncSnapshot`, `NostrAdapterMetrics` and `NostrReconciliationSummary` gain
variants or fields. External-signer account database keys move into the host
`SecretStore` on first open, so those accounts cannot be downgraded either.

`relay.damus.io` is no longer a retired relay; `relay.nostr.band` remains retired.

Account databases migrate from schema 101 through 107 on first open. The
attachment migrations keep payloads in place, so opening does not copy message
or attachment history. Back up before upgrading; downgrade is unsupported. See
the [storage-format contract](../marmot-architecture/storage-format-v2.md).

## Known issues

- [#2237](https://github.com/marmot-protocol/mdk/issues/2237): batched,
  oldest-first catch-up makes the #2086 loss much rarer, but it can still happen,
  for example when the only relay holding an old message is down. A message that
  arrives more than five epochs too late stays undecryptable without a "history
  may be incomplete" notice.
- WN Agent's control socket still grants its whole API to any authenticated
  client; capability-scoped grants remain tracked in
  [#1445](https://github.com/marmot-protocol/mdk/issues/1445).

## Release artifacts

- `v0.13.0`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.13.0`: WN Agent, terminal harness binaries (now including
  `wn-goose`), gateway plugins and checksum-paired installers. This track keeps
  its existing prerelease status.
- `marmotkit-v0.13.0`: iOS/macOS XCFrameworks, shared Swift source, platform privacy
  resources, Android Kotlin and all four JNI ABIs with `android-elf.json`, manifests
  and checksums.
- `marmotc-v0.13.0`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md).
