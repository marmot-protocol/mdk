# MDK 0.10.2

MDK 0.10.2 updates the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit.

For detailed client changes, default download policy, API adoption and validation, read
[the 0.10.1 → 0.10.2 integration guide](../integration/0.10.2.md). That guide was added
as a post-tag documentation supplement; published release links must use its merged
documentation commit, not the original `v0.10.2` tree.

## Highlights

- Accepted conversations acquire attachments in the background, including
  retained history. Protected checkpoints resume interrupted downloads when
  servers support validated ranges. Authentication completes before local
  bytes become available to clients.
- Swift/Kotlin and C expose bounded attachment history, local reads, progress,
  and durable cancel, retry, remove, and download-again controls. Automatic
  acquisition defaults on with per-account policy, storage quotas, disk reserve,
  and one transfer across accounts.
- Message projections expose accepted deletion provenance and preserve
  custom-event tags. Historical tombstones without evidence remain unknown.
- Local-first KeyPackage inventory distinguishes local ownership from relay
  observations. Compatible White Noise packages are preferred, and missing
  invitation packages produce an explicit error.
- Conversation opening and timeline projection avoid repeated account,
  profile, and message work. Readiness and contention measurements make delays
  easier to diagnose.
- Losing-branch messages remain parked for possible revival; retained replay
  and deferred-peel budget fixes avoid premature retirement.
- Account identity creation handles concurrent database initialization.
  Size-rotated audit segments retain source metadata.
- QUIC broker subscriber writes are bounded. Optimized macOS C libraries
  preserve Mach-O alignment for Xcode 27.

## Compatibility and adoption

Update generated Swift/Kotlin source and native libraries together from the
same immutable release. C consumers must update headers and libraries together
because message records have new fields. Rebuild downstream apps to adopt the
new APIs and behavior. The integration supplement also
[corrects C retry/compatibility guidance](../integration/0.10.2.md#c-compatibility-and-retry-guidance-corrections):
not every failed mutation is safe to retry, and C headers/libraries must match exactly.

Apple consumers must stage the matching shared Swift source and platform
privacy asset in their wrapper, rename the latter to `PrivacyInfo.xcprivacy`,
and declare `resources: [.copy("PrivacyInfo.xcprivacy")]`. Every consuming app
and extension must depend on that wrapper. See the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md) and
[consumer adoption tracking](https://github.com/marmot-protocol/mdk/issues/1874).
The existing native required-reason and SDK-signing questions remain open for
host App Store submission; resource validation does not resolve them.

Account databases advance through migrations 81–86: attachment history,
deletion provenance, retained attachment acquisition, worker demand,
protected partial downloads, and durable attachment controls. Back up or
export before upgrading. Downgrade after migration is unsupported; re-upgrade
or restore a pre-upgrade account database/export. Never remove migration rows.
See the [storage-format definition and compatibility evidence](../marmot-architecture/storage-format-v2.md).
Upgrades from before migration 47 also require at least 3.25 times the account
database size in free space for its table rebuild and gradual promotion.

## Release artifacts

- `v0.10.2`: MDK source snapshot.
- `wn-agent-v0.10.2`: WN Agent and terminal harness binaries, gateway plugins,
  and checksum-paired installers; this track retains prerelease status.
- `marmotkit-v0.10.2`: iOS/macOS XCFrameworks, shared Swift source, platform
  privacy assets, Android Kotlin and all four JNI ABIs, manifests and checksums.
- `marmotc-v0.10.2`: C ABI bundle and checksum.

Verify sibling SHA-256 files and manifest source/version metadata. Apple
binary ZIPs also provide SwiftPM checksums. Use matched release inputs.
