# MDK 0.10.0

MDK 0.10.0 is a new compatibility cohort for the Rust workspace, WN Agent,
MarmotKit (Swift/iOS, Swift/macOS, Kotlin/Android), and Marmot C. All four
release tags identify the same source commit. The release page records that
commit and the complete merged change list since 0.9.21.

## Highlights

- Bounded live chat-list windows, independent account-attention summaries,
  and combined live conversation windows expose paging, anchor recovery,
  revision-safe drafts, shared presentation, and viewer reaction state through
  the app runtime and bindings.
- Account-scoped user blocking returns across app surfaces. Pending invitations
  contribute to account attention without double-counting unread messages.
- CLI coverage expands to message edits, retention, disbanding, recovery,
  encrypted group images, Welcome redelivery, and ordered media operations.
- WN Agent adds the Claude Code terminal harness. Shared terminal harnesses
  clean up backend process groups, and Hermes preserves inbound obligations and
  quiet ambient context across restarts. Hermes and OpenClaw display current
  group names.
- Recovery fixes cover removed devices, re-addition and traffic arriving before
  a Welcome, interrupted peel replay, foreground scheduling, and local reset.
- Runtime work reduces unnecessary relay synchronization, subscription churn,
  directory/roster reads, and connection setup. Audit uploads validate and pin
  destinations on every attempt.
- Apple binding bundles now package privacy manifests in resource-bearing
  static frameworks. Consumers must preserve the complete XCFramework layout.

## Compatibility and adoption

This is a minor compatibility boundary before 1.0. Update generated Swift or
Kotlin source and native libraries together from the same immutable release.
Regenerate consumers and handle changed records/enums; do not combine 0.9.x
source with 0.10.0 libraries. Marmot C consumers should adopt the matching
header and library together. Review the [full changelog](../../crates/cli/CHANGELOG.md)
for CLI JSON changes, media epoch checks, attention totals, and harness behavior.

Account databases advance through migrations 70–75: forgotten groups, reset
cutoffs, chat-list paging, draft revisions, invitation attention, and user blocks.
Back up/export before upgrading. Downgrade after migration is unsupported;
re-upgrade or restore a pre-upgrade account database/export. Never remove
migration rows manually. See the [storage-format definition and compatibility
evidence](../marmot-architecture/storage-format-v2.md). Users upgrading from
before migration 47 must also allow at least 3.25 times the account database size
in free space for the table rebuild and gradual post-readiness promotion.

## Apple packaging and remaining host release checks

Apple bundles include SDK privacy resources inside each static framework.
Direct Xcode integrations must preserve the framework and use Embed & Sign;
SwiftPM and direct consumers must verify the final app archive contains the SDK
manifest. Binding generation and binary linking alone do not establish this.

The [Apple privacy audit](../../crates/marmot-uniffi/apple-privacy/README.md)
records outstanding SQLCipher `statfs`/`fstatfs` required-reason API questions,
file-metadata reachability review, and release XCFramework signing questions.
Publishing this SDK is not a claim that those App Store submission requirements
or host collector/privacy-label obligations have been resolved. Hosts must
resolve them before App Store submission and verify their signed app archives.
