# MDK 0.10.4

MDK 0.10.4 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.10.3 → 0.10.4 client upgrade guide](../integration/0.10.4.md) for required
record, schema and lifecycle changes.

## Highlights

- Token-aware text, reply, draft and media-send APIs return after durable local
  acceptance and preserve an opaque caller token through restart, engine handoff
  and timeline reprojection. Existing send APIs keep their completion semantics.
- Optional host-managed automatic attachment acquisition adds generation-fenced
  permission, idempotent demand and durable attempt limits. Existing clients stay
  in native automatic mode by default.
- Chat-list message previews carry the selected message's pinned retention duration
  and expiry so clients can hide expired content before periodic pruning.
- WN Agent control protocol v2 can create groups with optional founding relay routes.
  Hermes adds opt-in, sender-authorized reactions for approval prompts.
- Deferred pre-peel wrappers remain redeliverable, and epoch-backfill overflow uses
  execution-based exponential retry backoff. The latter is a pacing mitigation, not
  resumable or proven-lossless history recovery.
- MarmotKit builds compile target slices in parallel and verify their provenance
  agreement without changing published bundle names or layouts.

## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort
together. `MarmotOptions` / `MarmotClientOptions`, chat-list message previews,
timeline rows, attachment transfer states and error/status enums changed. Rebuild
consumers and update exhaustive matches and manually constructed records. Existing
non-token send APIs and native automatic attachment behavior remain supported.

Account databases migrate from schema 86 through 89. Migration 87 adds durable
automatic-acquisition history and budgets, 88 adds the draft descriptor covering
index, and 89 adds durable local submissions. Back up before upgrading; downgrade
is unsupported. Re-upgrade or restore a pre-upgrade database/export instead of
removing migration rows. Upgrades that skip older cohorts must also follow the
[previous guide](../integration/0.10.3.md) and
[storage-format contract](../marmot-architecture/storage-format-v2.md).

Preserve the matching Apple privacy resource in every consuming wrapper. Existing
required-reason and SDK-signing questions remain tracked in
[#1874](https://github.com/marmot-protocol/mdk/issues/1874); SDK artifact checks do
not establish consuming-app adoption, device performance or App Store acceptance.

## Release artifacts

- `v0.10.4`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.10.4`: WN Agent, terminal harness binaries, gateway plugins and
  checksum-paired installers. This track retains its existing prerelease status.
- `marmotkit-v0.10.4`: iOS/macOS XCFrameworks, shared Swift source, platform privacy
  resources, Android Kotlin and all four JNI ABIs, manifests and checksums.
- `marmotc-v0.10.4`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md).
