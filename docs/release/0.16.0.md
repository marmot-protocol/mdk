# MDK 0.16.0

MDK 0.16.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and
Android), and Marmot C from one source commit. See the
[0.15.0 → 0.16.0 client upgrade guide](../integration/0.16.0.md) for required
enum, event, deployment, storage and Rust API changes.

## Highlights

- Relay size limits. MDK no longer sends an event to a relay known to refuse
  it for size. Hosts can list limits in the deployment (`relayEventLimits`);
  the White Noise preset sets 2 MiB on its two relays, and for events over
  64 KiB a relay's advertised NIP-11 message size also counts. A group create
  or invite whose Welcome fits none of an invitee's inbox relays fails up
  front as `EventTooLarge { artifact: Welcome }`, before anything is created
  or sent. KeyPackage, block-list, sticker, profile, follow-list and relay-list
  publishes report size refusals as `EventTooLarge` too.
- A queued group change that no relay will take is retired once and announced
  as `QueuedIntentRefused` with reason `event_too_large`, the artifact and its
  size class, instead of being retried on every drain.
- Direct chats: `start_direct_conversation` (C `marmot_start_direct_chat`)
  reuses or creates the direct chat with a peer, with both accounts as
  founding admins, and a retry reuses the same group.
- Relay liveness for settings screens: per-account relay state, a live
  subscription and a reconnect for one configured relay.
- Audit log delivery and retention. v5 delivery no longer stalls on devices
  that keep many segments or retries silently forever. Hosts can read each
  account's delivery status, and set retention by age (1–30 days) and a
  per-account size budget, 256 MiB by default.
- Stuck groups. A group no longer stalls behind a full deferred-peel backlog
  (caps raised fourfold), and the recovery runner's hourly breaker rises from
  720 to 7,200 quanta, so a first catch-up of many groups no longer pauses
  the account. A group whose read of past state cannot restore its live state
  is quarantined as `RewindRestoreFailed` and repaired at the next open,
  rather than running on stale state.
- Commits settle correctly when a group relay is refused by the host-safety
  rule, when a relay URL is spelled with an upper-case host or explicit
  default port, and when a crash interrupted the send.
- WN Agent: `group_admin` reads, promotes, invites and removes a group member.
- Fixes: wiping a generated identity mid-setup no longer creates a stray
  account; a timed-out invite decline no longer leaves the group later;
  offline accounts stop repeating replay sync on every idle tick; an audit
  file a receiver's `409` blocked under 0.15.0 resumes delivery; relay replay
  storms no longer fill the audit log; live notifications reuse lookups across
  events, and directory queries overlap.

## Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact
cohort together.

- `AppGroupHydrationQuarantineReasonFfi` gains `REWIND_RESTORE_FAILED`
  (`.rewindRestoreFailed`). Exhaustive `switch`/`when` statements must add it.
- `GroupEventKindFfi.QueuedIntentRefused` gains `artifact` and `sizeClass`.
  Positional Swift patterns and Kotlin constructors or destructuring add them.
- `MarmotDeploymentFfi` gains `relayEventLimits` (default empty).
- `rotate_key_package`, `republish_key_package`, account setup's KeyPackage
  publish, `block_user`, `unblock_user` and `sync_sticker_packs` now fail as
  `EventTooLarge` when every relay refuses for size, where they returned
  `Runtime`, `BlockListUnavailable` or `StickerNetwork`.
- No `MarmotKitError` case, `MarmotEventFfi` case or C status is added.

C hosts must recompile: `MarmotGroupEventKind`'s `QueuedIntentRefused` body
appends three fields, and enum values are appended; none is renumbered.

Rust hosts: onboarding moves to `MarmotAppRuntime::account_setup()`;
`AppClient` and `MarmotApp::client` need the `test-support` feature; and
`MarmotDeployment`, `KeyPackagePublishError`, `PreparedSessionSend`,
`RuntimePerformanceOperation`, `AuditOtlpSendResult` and the engine's create
calls change. See the upgrade guide.

Storage: account databases are unchanged (no account migration). The shared
database migrates from schema 3 to 4 (`0004_audit_log_retention`) on first
open, and the local audit delivery cursor moves to version 2. Downgrade is
unsupported: 0.15.0 refuses both. Keep a device-local copy of the MDK data
directory before upgrading.

WN Agent and its plugins must be upgraded together: a 0.15.0 connector closes
the socket on `group_admin`.

## Known issues

- Follow-ups from the relay-safety work are open in
  [#3305](https://github.com/marmot-protocol/mdk/issues/3305): refused relays
  on the legacy Welcome path, a typed no-usable-relay error, and more. Sibling
  Welcomes, push-trigger gift wraps and other Welcome-carrying commits are not
  size-checked.
- Still open from 0.15.0:
  [#2237](https://github.com/marmot-protocol/mdk/issues/2237) (late messages
  more than five epochs behind),
  [#2277](https://github.com/marmot-protocol/mdk/issues/2277),
  [#2283](https://github.com/marmot-protocol/mdk/issues/2283),
  [#2389](https://github.com/marmot-protocol/mdk/issues/2389) and
  [#2286](https://github.com/marmot-protocol/mdk/issues/2286) (group-change
  prompts), [#2253](https://github.com/marmot-protocol/mdk/issues/2253) (group
  data extension order), [#2158](https://github.com/marmot-protocol/mdk/issues/2158)
  (an upload in flight across an epoch change is lost) and
  [#1445](https://github.com/marmot-protocol/mdk/issues/1445) (WN Agent's
  control socket grants its whole API to any authenticated client).
- Adding every device of an account remains best effort, a new send right
  after a reconnect can still go out ahead of older unsent ones, and the
  automatic-rejoin handshake's inner event kind is still under discussion
  ([marmot#451](https://github.com/marmot-protocol/marmot/issues/451)).

## Release artifacts

- `v0.16.0`: MDK source snapshot; workspace crates remain unpublished to crates.io.
- `wn-agent-v0.16.0`: WN Agent, terminal harness binaries, gateway plugins and
  checksum-paired installers.
- `marmotkit-v0.16.0`: iOS/macOS XCFrameworks, shared Swift source, platform
  privacy resources, Android Kotlin and all four JNI ABIs with
  `android-elf.json`, manifests and checksums.
- `marmotc-v0.16.0`: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also
have SwiftPM checksums. Follow the
[distribution guide](../../crates/marmot-uniffi/DISTRIBUTION.md). Dated
`0.16.0-nightly.*` builds are for testing only; pin this release instead.
